# Plan: Bun and Biome quality tooling for `web/`

## Goal

Give the Bun workspace a single, documented quality contract for Biome formatting and linting, strict TypeScript typechecking, deterministic tests, and production builds, then register those exact commands with the repository’s deterministic quality runner. Do not change todo application behavior or add another formatter/linter.

## Current state and assumptions

- `web/` is a Bun workspace containing `apps/api` and `apps/frontend`; the workspace already has passing Vitest tests and API/frontend production builds.
- The existing `lint` scripts are actually TypeScript `tsc --noEmit` invocations. These should become explicitly named `typecheck` scripts so `lint` can mean Biome linting.
- Vitest remains the existing test runner. “Bun-based” means dependencies and scripts are installed and invoked through Bun; replacing the test framework is unnecessary.
- `apps/frontend/src/routeTree.gen.ts` is generated by TanStack Router and explicitly says formatter/linter tools must exclude it.
- Existing uncommitted additions to `web/apps/api/package.json` and `web/bun.lock` (notably `@nestjs/platform-express`) are unrelated user work and must be preserved while updating the same files.
- No todo routes, services, UI behavior, persistence behavior, or tests need product-level changes for this task.

## Implementation steps

1. **Add Biome as the workspace’s only formatter/linter.**
   - Update `web/package.json` with a pinned `@biomejs/biome` development dependency, installed through Bun, and let `web/bun.lock` capture the resolved package without discarding existing lockfile changes.
   - Add `web/biome.json` using the schema/version corresponding to the installed Biome package.
   - Enable Biome’s formatter and recommended linter rules for the workspace, configure the repository’s established two-space/single-quote/no-unnecessary-semicolon style, and enable Git ignore-file handling so dependencies and build output remain out of scope.
   - Explicitly exclude `apps/frontend/src/routeTree.gen.ts` from formatting and linting because it is generated. Keep the configuration broad enough to cover maintained TypeScript, TSX, JavaScript, JSON, CSS, and supported project configuration files under `web/`.
   - Do not add ESLint, Prettier, or another overlapping tool.

2. **Expose clear Bun scripts at the workspace and app boundaries.**
   - In `web/package.json`, add:
     - `format` for the write-mode Biome formatter;
     - `format:check` for a non-mutating formatting check suitable for automation;
     - `lint` for Biome lint diagnostics;
     - `typecheck` to run every workspace package’s typecheck sequentially.
   - Preserve the existing workspace-level `test` and `build` scripts as the canonical deterministic test and production-build entry points, and retain development and migration scripts.
   - In `web/apps/api/package.json` and `web/apps/frontend/package.json`, rename the current TypeScript-backed `lint` responsibility to `typecheck` using each app’s existing `tsc --noEmit` configuration. Keep each app’s existing Vitest `test` command and real production `build` command (`tsc -p tsconfig.build.json` for the API and `vite build` for the frontend).
   - Ensure every root command is runnable from `web/` as `bun run <script>` and propagates a failing child/tool exit status.

3. **Bring maintained files onto the configured formatting/lint baseline.**
   - Run the write-mode formatter once over `web/` and commit only mechanical formatting/import-order fixes required by the new Biome rules.
   - Resolve any Biome lint findings with behavior-preserving source/config cleanup rather than blanket rule disabling. If an exceptional suppression is genuinely needed, keep it narrow and explain it inline.
   - Do not format or manually edit the generated TanStack route tree, dependency directories, or build outputs.

4. **Register the complete deterministic quality contract.**
   - Update the `web` project in root `projects.yaml` so its checks invoke the exact documented workspace commands from the configured `web/` working directory:
     1. `[bun, run, format:check]` with operation `format`;
     2. `[bun, run, lint]` with operation `lint`;
     3. `[bun, run, typecheck]` with operation `typecheck`;
     4. `[bun, run, test]` with operation `test`;
     5. `[bun, run, build]` with operation `build`.
   - Use an area label that accurately represents both frontend and API rather than the current frontend-only label, and retain practical timeouts (increasing test/build timeouts if needed). Keep commands as argv arrays with bare `bun`, as required by the factory quality configuration.

5. **Document setup and all developer/CI commands.**
   - Update `web/README.md` so prerequisites and installation remain Bun-first and the Commands section distinguishes:
     - `bun run format` (writes files),
     - `bun run format:check` (non-mutating verification),
     - `bun run lint`,
     - `bun run typecheck`,
     - `bun run test`,
     - `bun run build` (production output).
   - Retain the existing development, PostgreSQL, and migration instructions. State that the five non-mutating commands are the required deterministic quality checks and that they run across both applications where applicable.

## Verification

Run from `web/` after a clean `bun install` (or verify the existing install is synchronized with `bun.lock`):

1. `bun run format:check`
2. `bun run lint`
3. `bun run typecheck`
4. `bun run test`
5. `bun run build`

All five commands must exit successfully. Confirm the production build creates the existing API and frontend build outputs without requiring product behavior changes. Then run the repository quality entry point for the `web` project (or otherwise invoke the configured `projects.yaml` checks) to prove the deterministic runner executes the same five commands successfully. Finally, run `git status --short` and ensure generated `dist/`, `.tanstack/` temporary output, and `node_modules/` are not added, while `apps/frontend/src/routeTree.gen.ts` remains untouched.
